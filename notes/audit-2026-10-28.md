## Defects found and fixed

### P1-1 — "Listed only" toggle broken; unlisted positions never rendered (FIXED)

- Route: `#market` (Listings), all viewports.
- Root cause: `site/storefront.mjs` rendered with `ctx.lots.filter(matches)`. `matches`
  takes `(lot, listedOnly = state.listedOnly)`, so `Array.prototype.filter` passed the
  array **index** as `listedOnly`: index 0 always shown, every unlisted lot at index >= 1
  silently dropped, regardless of the checkbox.
- Evidence: unchecking "Listed only" left the table at 15 rows; expected ~500 unlisted
  active non-dust positions. Reproduced with `buildUnlistedLots(live.json, …)` = 500 lots
  in Node vs 0 rendered in browser.
- Fix: `visibleLots(lots, listedOnly)` helper; `renderTable` uses it. Regression tests
  added to `site/storefront.test.mjs` (3 cases).

### P1-2 — Sales panel table pushes page horizontal overflow at ≥720px (FIXED)

- Route: `#market`, viewports 1280 (overflow 54px) and 768 (173px).
- Root cause: global `table { min-width: 560px; table-layout: fixed }` in `site/app.css`
  leaked into `#sales-panel .sales-table`; the side panel (~380–480px) could not contain it.
- Fix: `#sales-body { overflow-x: auto }` and `#sales-panel .sales-table { min-width: 0;
  table-layout: auto }`. Verified 0px overflow at 1280/768/375.

### P1-3 — Position deep page kept market strip + Listings storefront visible (FIXED)

- Route: `#position/{id}`. The router set `body.view-position`, but no CSS acted on it, so
  the market strip, the Listings table and the Sales panel rendered above the position
  detail.
- Fix: added `body.view-position .market-strip, … .tabs, … .panel { display:none
  !important }` in `site/app.css`, mirroring the portfolio/incentives views. Verified:
  only `#position-panel` is visible on `#position/27`; `#position/999999999` shows the
  "Position not found" fallback without shell breakage.

## Findings not fixed (accepted / for owner decision)

- **P2 — optional rebate campaign files 404 on every route.** `site/rebate-claim.mjs`
  mounts on any page (it waits for `.inc-offers`, which `incentives.mjs` renders on every
  route) and fetches `rebates/28-52894.{campaign-params,tree,campaign}.json`. Dev server
  serves `site/`, which has no `rebates/` dir (files live in repo-root `rebates/` and are
  copied into `dist/`). In production only `tree.json` 404s (tree not published yet) —
  expected, handled gracefully. Not a required-request failure.
- **P2 — public RPC noise.** `base.drpc.org` returns 400 and `mainnet.base.org` 429 under
  load; `own-listings.mjs` falls back to `base-rpc.publicnode.com`, so own-listings reads
  degrade to the Seaport feed without breaking. Transient, graceful.
- **P2 — "Total Volume" tile source.** `updateTiles` computes `totalVolumeUsd` from
  `readListings()` (our VexyMarketplace contract), while the tooltip says "All-time USDC
  volume of external lANTS sales on the native marketplace". The Sales side panel uses the
  native trades feed instead, so the tile can read $0 while the panel shows real trades.
  Confirm the intended source; the two should not silently diverge.
- **P3 — Share button is not in the UI.** The plan catalog lists "Share", but no `.sf-share`
  is rendered (table and card builders omit it; `card-actions.mjs` keeps a dormant share
  handler). The `#position/{id}` link covers deep-linking. Accept as-is or add the button.
- **P3 — incentives + rebate panels initialize on every route.** `incentives.mjs` and
  `rebate-claim.mjs` build the full dashboard and run on-chain reads even when the user
  never visits `#incentives`. Recommend gating init on `body.view-incentives` to cut the
  404s and the extra `eth_getLogs` scans.
- **P3 — `.cta-btn` "Make an offer" carries `href="#offers"` but opens the modal**
  (`preventDefault`). Cosmetic; either navigate to Offers or keep the href honest.
